## 二つの文書が食い違っている

これが照会が必要な理由であり、照会文の形を決める。

| | 禁止の書き方 |
|---|---|
| API ページ 7. | **無条件**に「蓄積、編集および加工等は禁止」 |
| 規定 第18条 | **目的で限定**。第三者提供、営業使用、第三者提供目的の加工・再利用、自身の証券投資以外の目的 |

第18条には「蓄積」という語が無い。
逆に第18条は「お客様の証券投資のためにのみ利用する」ことを**前提として認めて**おり、
本件の用途（本人の投資判断と、その判断が正しかったかの事後検証）は
文言上そこに収まる余地がある。

一方 API ページ 7. をそのまま読めば、価格を 1 点保存することすら「蓄積」に当たる。

**厳しい方を採る。** 沈黙が同意でないのと同じく、
二つの規定が食い違うときに緩い方を自分に都合よく採らない。
だから現時点の判定は PROHIBITED であり、
覆せるのは同社からの書面の明示許諾だけである。

## なぜ「価格が取れる」だけでは足りないのか

本システムは `decision_price` / `decision_price_observed_at` /
`entry_reference_price` / `entry_price_observed_at` を保存できなければ
Prediction を作れない（DB 制約）。
蓄積を禁じる規約の下では、リアルタイム価格が無料で取れても
**Prediction は 1 件も作れない**。
D-06b は価格取得の問題ではなく、記録の適法性の問題である。
